# URML Layer 2 — Intent Primitives — v0.1.0

**Spec version:** 0.1.0 (pre-stable; per-artifact semver, breaking changes
allowed before 1.0.0)
**Status:** Normative. This is the specification document for Layer 2.
**Originating decision record:** [RFC-0002](../../docs/rfcs/0002-initial-primitive-vocabulary.md)
(core vocabulary), with profile additions authorized by RFC-0002
§Profile-extensibility and specified in the profile documents
([home](../profiles/home/README.md), [drone](../profiles/drone/README.md)).
RFC-0002 is the *why*; this document is the *what a runtime must implement*.
Where the two ever diverge, an RFC reconciles them; this document does not
drift silently.

---

## 1. Scope and conventions

Layer 2 defines the atomic vocabulary of robot intent: a closed set of typed
verbs that a Layer-3 behavior composes and a Layer-0 substrate executes. A
primitive carries intent, not implementation. `move_to(kitchen)` says go there;
the runtime decides how.

The key words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY**
in this document are to be interpreted as in RFC 2119.

This document specifies **twenty** primitives: **twelve core** verbs
meaningful across multiple profiles, and **eight profile-scoped** verbs
(`speak`, `listen` for the home profile; `take_off`, `land`, `return_to_home`
for the drone profile; `pick_from`, `place_at`, `swap_tool` for the industrial
profile). A conformant runtime MUST implement every core primitive it
declares conformance to; a profile runtime MUST additionally implement that
profile's added primitives. RFC-0002 §Reference-runtime-changes defines which
subset a drone runtime MUST implement (`grasp`, `release`, and object-pickup
`detect` are not required of a drone runtime).

Each primitive below is specified with a fixed section template:

- **Signature** — the YAML surface and argument types.
- **Semantics** — what the runtime MUST achieve, in one paragraph.
- **Capability requirements (Layer 1)** — the manifest fields that MUST be
  present for a program using the primitive to validate.
- **Safety-envelope checks** — the constraints the validator enforces *before*
  execution. A program that violates any of these MUST be rejected at
  validation time; execution MUST NOT begin.
- **Variable bindings** — what the primitive produces (if anything) and the
  shape of any `store_as` result.
- **Substrate sketches** — one ROS-2 and one non-ROS realization. Every
  primitive in this layer MUST satisfy the substrate-neutrality acid test: it
  is cleanly implementable on a runtime with zero ROS dependencies. The
  non-ROS sketch is the proof obligation, not decoration.

A primitive is a one-way door. Composition is preferred over expansion: if a
behavior can be expressed by composing existing primitives, that composition
is the answer, not a new primitive (RFC-0002 §Design-principle-1). Adding,
removing, or changing the semantics of a primitive is an RFC, never a PR.

### 1.1 Shared argument types

These types appear across multiple primitives and have one definition:

- **`<location>`** — an identifier resolving against
  `manifest.declared_locations` or the active world model.
- **`<pose>`** — `{x, y, z?, yaw?, pitch?, roll?}` in a declared `frame`.
- **`$name`** — a reference to a prior `store_as` binding (Layer-3 resolves
  scope; the validator type-checks the reference).
- **`<duration>`** — a time quantity (e.g., `30s`, `5m`).
- **`<speed>`** — a fraction of the manifest maximum, or an absolute value.
- **`<force>`** — `gentle | firm` or an absolute newton value.

### 1.2 The validator's per-primitive passes

The validator runs **five** passes per program. (RFC-0002 §Validator-changes
described four; Pass 5 was added by [RFC-0004](../../docs/rfcs/0004-compliance-policy.md)
and the connectivity coherence checks by
[RFC-0006](../../docs/rfcs/0006-connectivity-and-link-loss.md). This document
reflects the shipped validator, which is the normative reference.)

1. **Argument typing.** Required arguments present; optional arguments
   well-typed; mutually exclusive arguments not co-present.
2. **Capability check.** The Layer-1 manifest declares every field the
   primitive requires (including, where applicable, RFC-0006 `connectivity`
   role existence). A missing field is reported with the primitive, the field,
   the problem, and a suggested manifest addition.
3. **Safety-envelope check.** Profile-active envelope constraints are applied
   and conjoined across profiles (the strictest wins): geofence/perimeter
   containment, altitude bands, people-occupancy zones, endurance margins, and
   RFC-0006 link-loss-rule coherence.
4. **Variable-binding check.** `store_as` names are unique; every `$ref`
   resolves to a prior `store_as` of a compatible type.
5. **Compliance policy check.** When a `provenance` block is present, the
   active policy (RFC-0004; US-federal by default) is evaluated. Absent
   provenance, Pass 5 is skipped.

The structured error format (`{primitive, field, problem, suggestion}`) is the
contract the Layer-4 LLM bridge consumes to revise emissions. Error codes are a
stable public API (`reference/validator/src/urml_validator/errors.py`).

## 2. Core primitives

### 2.1 `move_to`

Go to a named location or a pose.

```yaml
- move_to:
    location: <name>             # mutually exclusive with `pose`
    pose: {x: ..., y: ..., z?: ..., yaw?: ..., pitch?: ..., roll?: ...}
    frame: <frame_id>            # required if `pose` is used
    carrying: $name              # optional; an object the robot is transporting
    speed: <fraction|absolute>   # optional override of manifest default
```

**Semantics.** The robot reaches the declared location or pose. The runtime
selects the trajectory; URML does not specify it. Completion is reported when
the robot is within the substrate's declared positioning tolerance. Exactly one
of `location` or `pose` MUST be set; `pose` MUST be accompanied by `frame`.

**Capability requirements (Layer 1):** `mobility` declared; a named `location`
MUST resolve against `manifest.declared_locations` or the active world model;
if `pose` is used, `frame` MUST be in `manifest.frames`.

**Safety-envelope checks:** the target is within the declared geofence / cell
perimeter / mapped area; the target altitude (if any) is at or below
`manifest.service_ceiling` and the active deployment cap; `speed` is at or
below `manifest.max_velocity` and any active cap.

**Variable bindings:** none. Errors (`target_unreachable`, `path_blocked`,
`envelope_violation`) are surfaced to Layer-3 `on_error`.

**Substrate sketches.** ROS-2: Nav2 `NavigateToPose`, or MoveIt 2 `MoveGroup`
for arm motion; goal status maps to URML completion. Non-ROS: PX4
`MAV_CMD_NAV_WAYPOINT` (global) or offboard setpoints (local frame); OPC UA
Robotics `MoveTo` method.

### 2.2 `dock`

Return to a declared station and optionally perform a service.

```yaml
- dock:
    at: <station_name>           # optional; default: manifest's primary dock
    service: <service>           # core: park (default), charge
                                 # profile-extensible: swap_battery, swap_tool, ...
    until: <full | duration | condition>  # optional; defaults per-service
```

**Semantics.** The robot navigates to the declared station, parks in its pose,
and (if `service` is non-default) initiates the requested service. The runtime
owns the station-specific procedure. The primitive blocks until the service is
complete or `until` is satisfied. `dock` is a primitive rather than `dock +
wait_for` because the composition cannot express atomic departure ("leave the
instant charge crosses 80%") and several services are not "park-then-wait" at
all (RFC-0002 §2 Composition-vs-expansion).

**Capability requirements (Layer 1):** `mobility` declared; the target station
declared in `manifest.docking_stations` with the requested `service` in its
declared services list.

**Safety-envelope checks:** the station is within the declared operational
area; `service` is in the active profile's enum; the robot's current state
allows the service (battery present for `charge`, gripper empty for
`swap_tool`).

**Variable bindings:** none by default. Status (`docked`, `service_complete`,
`service_aborted`) is available to Layer-3 `on_error`.

**Substrate sketches.** ROS-2: Nav2 `DockRobot` (Iron+) or a wrapped docking
server; service behaviors via separate action clients. Non-ROS: PX4
`MAV_CMD_NAV_LAND` + `MAV_CMD_DO_AUX_FUNCTION` for landing-pad services; OPC UA
`Dock` method with a `service` parameter.

### 2.3 `hover`

Actively maintain position against disturbances.

```yaml
- hover:
    over: $target | <location>   # optional; default: current position
    duration: <time>             # mutually exclusive with `until`
    until: <condition>           # mutually exclusive with `duration`
    tolerance: <distance>        # optional; default per manifest
```

**Semantics.** The robot actively maintains position (translation and yaw)
within the declared tolerance for the declared duration or until the declared
condition. Distinct from `wait`: `hover` MUST actively reject disturbances;
`wait` is passive. At most one of `duration` or `until` MAY be set.

**Capability requirements (Layer 1):** `mobility.station_keeping` is `true`
(multirotor drones, station-keeping underwater vehicles, satellites; ground
robots satisfy this trivially as "stay parked").

**Safety-envelope checks:** the hover location is within the declared
operational area; the duration does not exceed declared endurance (battery,
fuel) beyond the declared safety margin; under a no-fly-over-people constraint,
the hover pose does not overlap declared people-occupancy zones.

**Variable bindings:** none.

**Substrate sketches.** ROS-2: Nav2 position-hold/spin behavior; MoveIt 2
trajectory holding for arms. Non-ROS: PX4 `MAV_CMD_NAV_LOITER_TIME` /
`MAV_CMD_NAV_LOITER_UNLIM` with a condition watcher; OPC UA position-hold mode.

### 2.4 `wait`

Pause in place passively for a duration.

```yaml
- wait:
    duration: <time>             # required
```

**Semantics.** The robot halts active motion intent and waits for the declared
duration. Unlike `hover`, the runtime is not required to actively reject
disturbances (a drone MAY drift in wind; a wheeled robot MAY roll on a slope).
Profile constraints override: the drone profile rejects `wait` between
`take_off` and `land`.

**Capability requirements (Layer 1):** none beyond the general capability to
remain idle.

**Safety-envelope checks:** profile-active prohibitions (the drone profile
rejects in-flight `wait`; drones MUST `hover`).

**Variable bindings:** none.

**Substrate sketches.** ROS-2: a sleep node, or a no-op for the duration with
action clients held. Non-ROS: PX4 — ground-stationary contexts only, not in
flight; OPC UA no-op timer.

### 2.5 `wait_for`

Block until an external event, signal, or input.

```yaml
- wait_for:
    condition:                   # exactly one of:
      event: <event_name>
      signal: <signal_name>
      input: speech | text | gesture | button | external
      sensor_threshold: {sensor: <name>, op: <gt|lt|eq|ne|gte|lte>, value: <number>}
    timeout: <time>              # optional; default per-deployment
    on_timeout: error | continue # optional; default: error
    store_as: <name>             # optional; binds the resolved condition value
```

**Semantics.** The robot remains in its current state and blocks the program
until the declared condition becomes true or the optional timeout fires.
Exactly one condition kind MUST be set. Events and signals are declared in the
active profile; `speech`/`text` inputs are mediated by the Layer-4 bridge; the
rest by the substrate.

**Capability requirements (Layer 1):** the condition source MUST be a declared
input/sensor in `manifest.perception` or a declared event in
`manifest.declared_events`.

**Safety-envelope checks:** the wait pose is within the declared operational
area; the timeout does not exceed declared endurance beyond the safety margin.

**Variable bindings:** the resolved condition value (the user's input, the
sensor reading at threshold crossing) MAY be bound via `store_as`.

**Substrate sketches.** ROS-2: a subscription with a predicate matcher; a
bridge callback for `input: speech`. Non-ROS: PX4 parameter/telemetry-driven
event; OPC UA subscription on the matching node.

### 2.6 `grasp`

Close a gripper on a detected target, with a declared force.

```yaml
- grasp:
    target: $name                # required; a prior `detect` binding
    force: gentle | firm | <number>N   # optional; default per profile
    approach: top | side | front | auto # optional; default: auto
```

**Semantics.** The robot positions the end-effector for the declared approach,
closes the gripper on the target until contact (or positional limit), and
applies the declared force. Completion is reported on a stable grip.

**Capability requirements (Layer 1):** `manipulation.grippers` declared with at
least one gripper whose declared force range contains the requested force; the
`target` binding's object class is in that gripper's accepted-class list.

**Safety-envelope checks:** requested force is within the gripper's declared
range and at or below the active profile's ceiling (home defaults to
`gentle`); the target's declared position is within the gripper's reachable
workspace.

**Variable bindings:** none. Failure (`no_object_sensed`, `force_exceeded`)
is surfaced to Layer-3.

**Substrate sketches.** ROS-2: MoveIt 2 grasping with a gripper plugin; force
via the gripper action server. Non-ROS: OPC UA `Grasp` method with a force
parameter; vendor SDK grip API.

### 2.7 `release`

Open a gripper with a declared mode.

```yaml
- release:
    mode: drop | place | hand_to_user
    at: <location | pose>        # required iff mode == place
    height: <distance>           # optional; for `drop` and `place`
```

**Semantics.** The robot opens the gripper per mode: `drop` opens at the
current pose (object falls); `place` moves to `at` (with `height` offset),
opens, and verifies support before retreating; `hand_to_user` presents the
object to a declared `user` location and opens only when the substrate signals
the user has taken it (or after a profile timeout). `place` MUST declare `at`.

**Capability requirements (Layer 1):** `manipulation.grippers` declared; for
`mode: place`, the target location is reachable.

**Safety-envelope checks:** for `drop`, drop height does not exceed the
profile-declared maximum (home defaults low to protect breakables); for
`hand_to_user`, the user location is within the reachable workspace.

**Variable bindings:** none.

**Substrate sketches.** ROS-2: MoveIt 2 release; a force-monitoring callback
triggers `hand_to_user`. Non-ROS: OPC UA `Release` method with a `mode`
parameter; vendor grip-open API.

### 2.8 `detect`

Find an object matching criteria and bind it to a variable.

```yaml
- detect:
    object: <class_name>         # required; must be in declared object vocabulary
    attributes:                  # optional; class-specific
      color: <name|hex>
      size: small | medium | large | {dim: <number>}
      tag: <id>
    where:                       # optional; constrain search
      near: $reference | <location>
      within: <distance>
    store_as: <name>             # required if referenced later
```

**Semantics.** The perception pipeline searches for an object of the declared
class and attributes within the declared region (or the full perceivable
workspace if `where` is omitted). On success the binding includes class, pose,
and reported attributes. On failure, `not_found` surfaces to Layer-3.

**Capability requirements (Layer 1):** `perception` declared with at least one
sensor capable of detecting the requested class; the class is in the manifest's
declared object vocabulary.

**Safety-envelope checks:** the declared search region is within the
operational area.

**Variable bindings:** `store_as` resolves to a structured object with at least
`{class, pose, frame, attributes, confidence}`.

**Substrate sketches.** ROS-2: a perception pipeline on camera/depth topics
with a request/response action. Non-ROS: PX4 companion-computer perception
streamed via MAVLink, or a ROS-less perception service; OPC UA `FindObject`
method.

### 2.9 `scan`

Survey an area with a declared pattern; produce structured perception data.

```yaml
- scan:
    area: <polygon | bounding_box | named_region>
    pattern: serpentine | spiral | grid | adaptive   # default: serpentine
    overlap: <fraction>          # optional; default 0.3 (serpentine/grid)
    altitude: <distance>         # optional; aerial scans (drone aliases pose.z)
    media: photo | video | sensor_only  # optional; default: photo
    sensor: <sensor_name>        # optional; default: primary camera
    store_as: <name>             # required
```

**Semantics.** The robot follows the declared pattern over the declared area,
collecting structured perception data at each sampling point. Exactly one of
`polygon`, `bounding_box`, or `named_region` MUST define the area. The binding
includes per-sample data and an aggregated summary.

**Capability requirements (Layer 1):** `mobility`; `perception` with the
declared sensor; for aerial scans, flight capability and a service ceiling at
least the declared altitude.

**Safety-envelope checks:** the area and the pattern-derived path stay within
the operational envelope; for aerial scans, altitude is within both the
service ceiling and the active cap; no sample point overlaps a declared
people-occupancy zone without an explicit manifest override.

**Variable bindings:** `store_as` produces `{samples: [...], coverage:
<fraction>, anomalies: [...]}`.

**Substrate sketches.** ROS-2: Nav2 path-following with a per-waypoint
perception callback. Non-ROS: PX4 pattern uploaded as a `MISSION` with camera
triggers (`MAV_CMD_DO_DIGICAM_CONTROL`); OPC UA `RunScan` method.

### 2.10 `measure`

Take a single reading and bind it.

```yaml
- measure:
    what: distance | temperature | weight | pressure | <declared>
    target: $name | <location>   # optional; default: current pose
    sensor: <sensor_name>        # optional; default: declared sensor for `what`
    store_as: <name>             # required
```

**Semantics.** The robot takes one reading with the declared sensor and binds
the result. Distinct from `scan` (surveys an area, produces a collection) and
`detect` (produces an object reference, not a scalar).

**Capability requirements (Layer 1):** `perception` declares a sensor capable
of the requested measurement type.

**Safety-envelope checks:** the target is within the sensor's declared range.

**Variable bindings:** `store_as` produces `{value, unit, timestamp,
confidence?}`.

**Substrate sketches.** ROS-2: subscribe to the sensor topic, take one
message, return. Non-ROS: PX4 read the sensor's MAVLink stream; OPC UA `Read`
on the node.

### 2.11 `capture`

Capture a media artifact (photo or video) and bind a handle.

```yaml
- capture:
    media: photo | video
    target: $name | <location | pose>   # optional; default: current view
    duration: <time>                    # required iff media == video
    attributes: {resolution?, format?, frame_rate?}   # optional
    store_as: <name>                    # required
```

**Semantics.** The declared camera captures the requested media: a still for
`photo`, a recording of `duration` for `video`. `media: video` MUST declare
`duration`; `media: photo` MUST NOT. If `target` is set and the camera is
movable, the camera is pointed first; a fixed camera with an out-of-frame
target is rejected at validation.

**Capability requirements (Layer 1):** `perception.cameras` declared with a
camera supporting the requested mode; if `target` is set,
`cameras[i].movable: true` (the validator catches the fixed-camera case
statically).

**Safety-envelope checks:** for video, duration does not exceed the declared
storage/endurance budget beyond the safety margin; capture in a
profile-declared privacy-restricted zone requires an explicit manifest
override.

**Variable bindings:** `store_as` produces a media handle `{type, format,
size, timestamp, pose, frame, uri}`; the substrate decides where the bytes
live. `media: stream` and unbounded recording are deferred (RFC-0002
§Unresolved-questions).

**Substrate sketches.** ROS-2: `image_transport` for photos; a ROS bag or
configured sink for video. Non-ROS: PX4 `MAV_CMD_DO_DIGICAM_CONTROL` /
`MAV_CMD_VIDEO_START_CAPTURE`; OPC UA `TakeImage` / `StartRecording`.

### 2.12 `report`

Send structured information upstream.

```yaml
- report:
    to: user | log | caller | <named_endpoint>   # default: user
    facts: {<key>: <value>, ...}   # required
    attachments: [$name, ...]      # optional; media handles from `capture`
    status: success | partial | failure   # optional; default: success
    severity: info | notice | warning | error  # optional; default: info
```

**Semantics.** The runtime serializes the declared facts and any attached
handles and emits to the destination. `to: user` is rendered to natural
language by Layer 4; `to: log` writes a structured entry; `to: caller` returns
to the invoker.

**Capability requirements (Layer 1):** the declared destination is reachable
per the manifest's declared `outputs`.

**Safety-envelope checks:** none beyond destination validity.

**Variable bindings:** none.

**Substrate sketches.** ROS-2: publish a structured message on a configured
topic; return through the bridge for `to: user`. Non-ROS: PX4 `STATUSTEXT`
plus MAVLink FTP for attachments; OPC UA write to a configured node.

## 3. Profile-scoped primitives

RFC-0002 §Profile-extensibility authorizes profiles to add primitives. These
are not part of the core; a runtime implements them only when it declares
conformance to the owning profile. Each still satisfies the substrate-neutrality
acid test.

### 3.1 `speak` — home profile

Emit a spoken utterance to the user.

```yaml
- speak:
    utterance: <string>          # required
    locale: <BCP-47>             # optional; default: manifest primary_locale
    style: notice | warning | conversational   # optional; default: conversational
    interrupt: true | false      # optional; default: false
```

**Semantics.** The robot pronounces `utterance` through its declared
speech-output channel. `style` is advisory to voice rendering. `interrupt:
true` is for safety messages; the default queues behind any in-progress
utterance to keep conversational flow predictable.

**Capability requirements (Layer 1):** `manifest.outputs.named_endpoints`
declares `speech`. A manifest without `speech` rejects programs using `speak`.

**Safety-envelope checks:** none beyond capability declaration
(deployment-declared do-not-disturb hours are deferred).

**Variable bindings:** none.

**Substrate sketches.** ROS-2: publish a TTS message, routed through a TTS node
(`audio_common`). Non-ROS: OPC UA `Speech.Utter()`; vendor TTS API. Not
applicable to PX4 (drones operate outside conversational range).

### 3.2 `listen` — home profile

Block until the user provides spoken input (or a declared timeout).

```yaml
- listen:
    prompt: <string>             # optional; spoken before listening
    locale: <BCP-47>             # optional; default: manifest primary_locale
    timeout: <duration>          # optional; capped by envelope
    expected: free_form | confirmation | choice   # optional; default: free_form
    choices: [<string>, ...]     # required iff expected == choice
    store_as: <name>             # required if referenced later
```

**Semantics.** The robot listens on its declared speech-input channel. If
`prompt` is set, the robot speaks it first (the validator treats the
speak+listen pair atomically). `expected: choice` maps the transcription to the
closest `choices` entry and MUST declare a non-empty `choices`; `confirmation`
extracts a yes/no judgment.

**Capability requirements (Layer 1):** `manifest.perception.sensors` declares a
sensor with `measurement_type: speech`. A manifest without speech input rejects
programs using `listen`.

**Safety-envelope checks:** the `timeout` does not exceed the envelope's
`max_listen_duration` (v0.1 enforces only that the timeout is declared finite).

**Variable bindings:** `store_as` resolves to `{transcription, confidence,
choice_index}` (`choice_index` is `null` for `free_form`/`confirmation`, an
integer index into `choices` for `choice`).

**Substrate sketches.** ROS-2: a configured STT topic; the adapter buffers,
applies `expected`, and returns. Non-ROS: OPC UA `Speech.Listen(timeout)`;
vendor STT API.

### 3.3 `take_off` — drone profile

Begin flight: ascend from the current ground position to a declared altitude.

```yaml
- take_off:
    altitude: <distance>         # required; meters; frame per manifest (default agl)
    climb_rate: <speed>          # optional; m/s; substrate default if omitted
```

**Semantics.** The drone executes its substrate-specific takeoff (arming,
spin-up, ascent) and is airborne when the declared altitude is reached.
Programs exceeding the envelope's `max_altitude` are rejected at validation,
not runtime.

**Capability requirements (Layer 1):** `mobility.drive_type` in (`multirotor`,
`vtol`); `mobility.service_ceiling >= altitude`; the aerial frame (`agl` or
`wgs84`) declared in `manifest.frames`.

**Safety-envelope checks:** `altitude` is at or below the strictest of
(`manifest.mobility.service_ceiling`, `envelope.max_altitude`); weather
thresholds where the substrate exposes them at validation time.

**Variable bindings:** none.

**Substrate sketches.** ROS-2: `mavros/cmd/takeoff`, or `arm` + `takeoff` via
`mavros/cmd/arming` and `mavros/cmd/takeoff`. Non-ROS: PX4
`MAV_CMD_NAV_TAKEOFF`; OPC UA `Flight.TakeOff(altitude)`.

### 3.4 `land` — drone profile

End flight: descend from current position to a declared landing location.

```yaml
- land:
    at: <location | pose> | null # optional; default: current (x,y) at ground
    precision: standard | precise  # optional; default: standard
```

**Semantics.** The drone executes its substrate-specific landing at the
declared location (or directly below if `at` is omitted). `precision: precise`
requests fiducial-aided landing where supported; `standard` is GPS-aided.
Grounded when the substrate reports motors stopped.

**Capability requirements (Layer 1):** `mobility.drive_type` in (`multirotor`,
`vtol`, `fixed_wing`); fixed-wing landing requires a declared runway pose; a
named `at` MUST resolve against `manifest.declared_locations`.

**Safety-envelope checks:** the landing location is within the geofence;
declared people-occupancy zones do not intersect the landing approach.

**Variable bindings:** none.

**Substrate sketches.** ROS-2: `mavros/cmd/land`; layer `apriltag_ros` for
precision. Non-ROS: PX4 `MAV_CMD_NAV_LAND` / `MAV_CMD_NAV_LAND_LOCAL`; OPC UA
`Flight.Land(location)`.

### 3.5 `return_to_home` — drone profile

Abort current flight intent, return to the declared home location, then land.
The drone profile's canonical safety primitive; a program author can always
reach for `return_to_home` to gracefully terminate. It is the action a
declared RFC-0006 link-loss policy most commonly invokes.

```yaml
- return_to_home:
    speed: <speed>               # optional; m/s; substrate default if omitted
    altitude: <distance>         # optional; m; substrate RTH altitude if omitted
```

**Semantics.** The drone aborts the current flight intent, climbs to the
declared (or substrate-default) RTH altitude, navigates to the declared home
location, descends, and lands. The substrate owns the procedure; URML
expresses the intent.

**Capability requirements (Layer 1):** `mobility.drive_type` in (`multirotor`,
`vtol`, `fixed_wing`); a declared location named `home` in
`manifest.declared_locations` (the convention reduces ambiguity even where the
substrate uses `home` semantics regardless of name). When invoked from a
link-loss policy, RFC-0006 Pass-3 coherence additionally requires an aerial
drive type and a declared governed link role.

**Safety-envelope checks:** the declared RTH altitude is at or below
`envelope.max_altitude` and `manifest.mobility.service_ceiling`.

**Variable bindings:** none. After completion the drone is grounded;
subsequent flight primitives require an explicit `take_off`.

**Substrate sketches.** ROS-2: `mavros/cmd/return_to_launch`. Non-ROS: PX4
`MAV_CMD_NAV_RETURN_TO_LAUNCH`; OPC UA `Flight.ReturnHome()`.

### 3.6 `pick_from` — industrial profile

Pick a detected object from a declared station. Convenience over the
`move_to(source) + detect(object) + grasp($target)` composition for the
single most frequent industrial pattern. Added by
[RFC-0013](../../docs/rfcs/0013-industrial-layer2-primitives.md).

```yaml
- pick_from:
    source: <station_name>           # required; resolved against declared_locations
    object: <class>                  # required; resolved against object_vocabulary
    attributes: { color: red, ... }  # optional; same shape as detect.attributes
    force: gentle | firm | <newtons> # optional; default per gripper
    store_as: <name>                 # required if subsequent steps reference $name
```

**Semantics.** Navigate to `source`, detect an object matching `object` +
`attributes` in the station's pickup zone, grasp it with the declared force.
Equivalent to the three-primitive composition; the substrate MAY map it to a
single configured station operation.

**Capability requirements (Layer 1):** `mobility`; `source` ∈
`declared_locations`; `perception` with at least one camera or sensor and
`object` ∈ `perception.object_vocabulary`; `manipulation` with a gripper whose
force range covers the requested force.

**Safety-envelope checks:** the inherited `move_to` and `grasp` checks
(velocity ceiling, `grasp.force` ≤ `gripper.force_max_n` and ≤
`envelope.max_grip_force_n` when set).

**Variable bindings:** binds an `object` (same payload shape as `detect`) under
`store_as`, consumable by `place_at.held`, `grasp.target`, `move_to.carrying`.

**Substrate sketches.** ROS-2: Nav2 navigate + perception query + MoveIt 2
grasp composed in the executor, or a single station-controller action.
Non-ROS: OPC UA Robotics `Manipulation.PickFrom(station, object)`; PLC
pick-at-station function block.

### 3.7 `place_at` — industrial profile

Place a held object at a declared station. Symmetric to `pick_from`;
convenience over `move_to(target) + release(mode: place|drop)`. Added by
[RFC-0013](../../docs/rfcs/0013-industrial-layer2-primitives.md).

```yaml
- place_at:
    target: <station_name>           # required; resolved against declared_locations
    held: $name                      # required; $ref to a prior pick_from/detect binding
    mode: place | drop               # optional; default: place
    height: <distance>               # optional; advisory in v0.1 (drop mode only)
```

**Semantics.** Navigate to `target` carrying the resolved `held` object,
release it with the declared mode at the target. `height` is accepted and
schema-validated but advisory in v0.1 — the manipulation surface carries no
height parameter (see RFC-0013 Unresolved questions).

**Capability requirements (Layer 1):** `mobility`; `target` ∈
`declared_locations`; `manipulation` with at least one gripper.

**Safety-envelope checks:** the inherited `move_to` and `release` checks.

**Variable bindings:** consumes `held` (must resolve to an `object`); produces
none.

**Substrate sketches.** ROS-2: Nav2 navigate(carrying) + MoveIt 2 release with
place/drop mode. Non-ROS: OPC UA `Manipulation.PlaceAt(station)`; PLC
place-at-station function block.

### 3.8 `swap_tool` — industrial profile

Change the end-of-arm tool at a declared tool-change station. Added by
[RFC-0013](../../docs/rfcs/0013-industrial-layer2-primitives.md).

```yaml
- swap_tool:
    at: <station_name>               # required; station must declare a `swap_tool` service
    to: <tool_name>                  # required; the tool to mount
```

**Semantics.** Move to the tool-change station and execute the substrate's
tool-change procedure. `swap_tool` rides the declared docking-station service
mechanism: the station named by `at` MUST be in `manifest.docking_stations`
and MUST declare the `swap_tool` service (the same surface `dock(service:
...)` uses). The per-station `accepted_tools` field is deferred, so `to` is
not validated against an accepted-tool list in v0.1.

**Capability requirements (Layer 1):** a `manifest.docking_stations` entry
named `at` declaring the `swap_tool` service. Unlike `dock`, `at` is required
(no default-station fallback).

**Safety-envelope checks:** none beyond the station being reachable; a future
RFC may add tool-membership and reach-window checks when `accepted_tools`
lands.

**Variable bindings:** none.

**Substrate sketches.** ROS-2: a tool-change action behind the station's
`swap_tool` service, dispatched through the same `send_docking_goal` path as
`dock`. Non-ROS: OPC UA Robotics `ToolChanger.ChangeTo(tool)` exposed as the
station service; PLC tool-change function block. Flight substrates do not
implement tool change and need no code for it — the dispatch verb already
exists on every adapter.

## 4. Conformance

A conformant runtime, given a valid manifest and a program:

- MUST execute each primitive it declares conformance to per the documented
  semantics, in a simulated or real environment.
- MUST reject (via the validator, before execution) every program that
  violates a documented safety-envelope check.
- MUST surface the documented error codes; they are a stable public API.

The machine-checkable expression of these requirements is the conformance
suite (`/conformance/fixtures/`), one or more positive and negative fixtures
per primitive. The per-primitive coverage of spec → schema → reference impl →
conformance fixture → runnable example is tracked in
[`docs/spec-coverage.md`](../../docs/spec-coverage.md).

## 5. Versioning and stability

This document is `layer-2-primitives@0.1.0`. Pre-`1.0.0`, breaking changes are
allowed but MUST go through an RFC that updates RFC-0002 and this document in
the same change. The twenty primitives here are the v0.1 vocabulary; the
core stays under the Manifesto's thirty-primitive ceiling, and new verbs face
the composition-over-expansion bar in RFC-0002 §Design-principles
(`pick_from`/`place_at`/`swap_tool` cleared it via RFC-0013).
