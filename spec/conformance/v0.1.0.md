# URML Substrate Conformance — v0.1.0

**Status:** Normative. This document defines what it means for a runtime to be
**URML-compatible**. It adds no primitive, no manifest field, and no behavior
semantics; it writes down a boundary that already holds for every reference
runtime, so the universality claim ("one sentence runs on any substrate") is
provable rather than asserted. Specified by
[RFC-0014](../../docs/rfcs/0014-substrate-conformance.md). The key words MUST,
MUST NOT, SHOULD, and MAY are to be interpreted as in RFC 2119.

This specification is part of the [Core Commitment](../../CORE_COMMITMENT.md):
it is, and will remain, Apache-2.0. Only the *certification service* that
attests runtimes against it (the *URML-Certified* trademark, §3) may be
commercial; the bar itself is open.

## 1. Scope

A URML *runtime* takes a validated URML program plus a Layer-1 capability
manifest and drives a substrate (ROS 2, PX4, AUTOSAR Adaptive, OPC UA Robotics,
a vendor SDK, a simulator, or one not yet built). This document states the
obligations a runtime MUST satisfy to be called URML-compatible, the tiers in
which compatibility is claimed, and the loop a runtime author MUST follow when a
substrate cannot express something. It is the human-readable contract whose
executable form is the conformance suite (`/conformance/`).

## 2. The conformance contract

A runtime is **URML-compatible** if and only if it satisfies all six clauses.
Each clause already holds for every reference runtime; this specification names
them, it does not invent them.

1. **Manifest intake.** The runtime accepts a valid Layer-1 capability manifest
   (`manifest_version: "0.1"`, `extra: forbid`) and refuses to execute a program
   that is not expressible under that manifest. It MUST NOT require any manifest
   field beyond the published Layer-1 schema.

2. **Frozen substrate Protocol.** The runtime provides an adapter implementing
   the substrate Protocol
   ([`reference/ros2-runtime/src/urml_ros2_runtime/substrate/base.py`](../../reference/ros2-runtime/src/urml_ros2_runtime/substrate/base.py)):
   every method, returning the published `SubstrateResult` subtypes, **failures
   returned, not raised**. A primitive the substrate genuinely cannot perform
   returns an unsuccessful `SubstrateResult` with a clear reason; it MUST NOT
   crash and MUST NOT silently no-op.

3. **Validate-before-actuate.** The runtime runs the full validator pass set
   (argument typing → capability → safety envelope → variable bindings →
   compliance policy) before a single actuator command is issued. A runtime that
   exposes a path which actuates without validation is **not** URML-compatible at
   any tier. This is a safety and liability boundary, not a performance tunable.

4. **Offline.** Once a program is validated, execution completes with no
   mandatory network or cloud dependency. Optional telemetry is opt-in and
   documented. A runtime that cannot run a validated program air-gapped is not
   URML-compatible.

5. **Zero-ROS acid test.** The substrate Protocol contains no ROS type and no
   ROS assumption. A URML-compatible runtime MAY use ROS internally but MUST NOT
   require the URML layer above it to. This makes the project's standing acid
   test ("can it be cleanly implemented on a runtime with zero ROS
   dependencies?") a normative gate. The PX4, marine, OPC UA, cobot, MuJoCo, and
   embedded runtimes are the standing evidence that the test is satisfiable.

6. **Conformance suite.** The runtime passes the conformance suite
   (`/conformance/`) for the profiles it claims, run through `ConformanceRunner`
   with the runtime's own adapter via the `adapter_factory` hook. The suite is
   the executable embodiment of this contract; this document is its rationale.

## 3. Conformance tiers

Two tiers, deliberately only two, mirroring the honest split in
[`conformance/README.md`](../../conformance/README.md):

- **Self-reported URML-compatible.** The runtime's authors run the conformance
  suite and publish the result. No third party is involved. This tier is free,
  requires no trademark, and is the only tier that exists in Phase 0. It is a
  factual claim ("the suite passes for profiles A, B"), not an endorsement. A
  runtime records its self-report in its own `CONFORMANCE.md`, naming the spec
  versions and profiles it passes.

- **URML-Certified.** A future, separately-operated program (outside this
  repository, per the commercial-surround separation in `CLAUDE.md`) attests a
  runtime against this specification and licenses the *URML-Certified*
  trademark. This document defines only the *bar*; it does not create the
  program, set a price, or bless any vendor. Naming the tier here is what lets
  that program exist later without re-litigating the technical contract.

There are no numeric levels, scores, or star ratings. A runtime is compatible
for the profiles whose conformance fixtures it passes, and not for the others.
A richer grading scheme before there is a single external runtime to grade would
be premature taxonomy.

## 4. The spec-gap loop (normative)

When a substrate genuinely cannot express something with the existing primitives
and the published manifest schema, the runtime author MUST NOT add a primitive,
widen a schema, or change a primitive's semantics to make it fit. The required
sequence is:

1. **Record** the need in the runtime package's `SPEC-GAPS.md`, stating whether
   it is *composable* from existing primitives (then document the composition —
   it is not a gap) or *genuinely inexpressible*.
2. **File an RFC Draft** for a genuinely inexpressible need, describing it. The
   substrate ships against the frozen Protocol with that capability returning an
   unsuccessful `SubstrateResult` until the RFC is accepted.
3. **Decide in the open.** The maintainer (Phase 0) decides the RFC on its own
   merits. A primitive is a one-way door (RFC-0002, `CLAUDE.md`); the gap loop
   exists so that door is only ever opened deliberately and in writing.

This formalizes, as project doctrine, the rule that integration work surfaces
spec gaps as *proposals*, never as silent expansion. RFC-0016 (`realtime`),
RFC-0019 (AUTOSAR `ara::com` binding), and RFC-0020 (Autoware AV primitives) are
worked examples: each was surfaced by a runtime build, recorded, and filed as an
RFC rather than bent into an existing primitive.

## 5. Relationship to other documents

This specification cites and MUST NOT contradict: `CLAUDE.md` (the acid test and
the Core Commitment), [`CORE_COMMITMENT.md`](../../CORE_COMMITMENT.md) (the
conformance suite — and this specification — are Apache-2.0 forever; only the
certification service is commercial), [`conformance/README.md`](../../conformance/README.md)
(the self-reported-vs-certified split this document formalizes), and the
[Layer-1 HAL spec](../layer-1-hal/v0.2.0.md) (substrate-neutral manifest intake).
The Layer-1 through Layer-4 specs and the profile specs are unchanged by this
document.

## 6. Versioning and stability

This document is `conformance@0.1.0`, versioned independently like every other
spec artifact (`spec/README.md` §Versioning). Pre-`1.0.0`, the contract may be
refined through RFCs that update it; `1.0.0` is the first stability commitment,
at which point the six clauses become a frozen compatibility surface a
certification program can rely on.
